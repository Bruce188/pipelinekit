# File size limit

A hand-written text file (code, tests, markdown) has at most 1,500 lines and 50,000 bytes. Claude Code's Read tool returns a text file whole only up to 25,000 tokens and past that a first page, so a longer file is read in pieces or only in part. The global `pre-commit` hook runs `~/.claude/hooks/filesize.py` on the staged files. `git merge` does not run `pre-commit` for a merge it makes without conflicts, so the global `pre-merge-commit` hook runs the same check on the merged files before the merge is recorded (see [Git hooks](components.html#git-hooks)):

- A commit or merge that adds a file over the limit, or takes a file from under the limit to over it, is refused with `[pre-commit.file-size]`. The refusal names each file, its lines and bytes, and what it was before; a control character in a path is shown as `?`, and a byte that is not UTF-8 as an escape. The event log gets the first path and its size, never the content. A refused merge is left unfinished: split the file, then `git commit` concludes the merge, and `pre-commit` checks it again.
- A file that was already over the limit before the commit gets a warning with `[pre-commit.file-size-over]`, and the commit goes through. A renamed file keeps the size it had under its old name; when a commit concludes a merge, or `git merge` records one, a file over the limit in either parent counts as already over.
- Binary files (a NUL byte in the first 8,000 bytes, or `binary` or `-diff` in `.gitattributes`), deleted files, symlinks and submodules are never counted. Attributes are read from the staged `.gitattributes`, so an unstaged edit there exempts nothing. A blob over 50,000 bytes is read in pieces and dropped once its first 8,000 bytes show it is binary.
- Generated, vendored, lock and data files are exempt. By default that is: lock files `*.lock`, `*.lockb`, `*.lockfile`, `*-lock.json`, `*-lock.yaml`, `npm-shrinkwrap.json`, `packages.lock.json`, `Package.resolved`, `go.sum`; vendored folders `vendor/`, `vendored/`, `third_party/`, `third-party/`, `node_modules/`; generated files and folders `generated/`, `__generated__/`, `dist/`, `*.min.js`, `*.min.css`, `*.map`, `*.generated.*`, `*.g.cs`, `*.g.dart`, `*.freezed.dart`, `*.designer.cs`, `*.Designer.cs`, `*ModelSnapshot.cs`, `*.pb.go`, `*_pb2.py`, `*_pb2.pyi`, `*.snap`; project and designer files an IDE writes `*.pbxproj`, `*.xcstrings`, `*.storyboard`, `*.xib`, `*.resx`; data files `*.json`, `*.jsonl`, `*.ndjson`, `*.geojson`, `*.csv`, `*.tsv`, `*.ipynb`, `*.svg`. A path marked `linguist-generated` or `linguist-vendored` in `.gitattributes` is exempt too.
- A project exempts more paths in `.file-size-exempt` at the repository root, one pattern per line, gitignore style: `name` matches a file or folder of that name at any depth, `name/` only a folder and everything in it, a pattern with a `/` in front or in the middle is anchored to the root, `*`, `?` and `[...]` (one character of a set, such as `[ch]` or `[a-z]`; `[!...]` or `[^...]` one character not in it) stay inside one folder and `**` crosses folders. `#` starts a comment; `!` lines are skipped. The staged copy of the file counts, else the one in the working tree. A file that passes only because an unstaged list in the working tree names it gets a note with `[pre-commit.file-size-exempt-local]`, and the event log records an override with its path and size, so a local exemption is never silent; to keep such a list out of commits, name it in `.git/info/exclude`. A list that is a link, a folder, cannot be read or is not UTF-8 text is not used, and the hook warns that it is not. This repository lists `documentation/`, the rendered pages.
- A check that fails to run warns with `[pre-commit.file-size-failed]`, records an error and lets the commit or merge through.
